# 长期规划：双路线 + 基建重构

## 现状

项目已完成核心玩法闭环：四幕推演 → 结局传记/世界报告。当前代码以验证核心玩法和提示词工程可行性为目标，很多设计是快速验证的结果，积累了较多技术债。

## 路线规划

未来分两条产品路线，共享同一套生成引擎和工具链，但面向不同的用户群体。

### A 路线：快节奏娱乐（面向大众玩家）

**定位**：轻量、爽快、低门槛。玩家打出天马行空的决策卡牌，快速获得戏剧性反馈。

**关键方向**：

- **剧本组解锁**：完成一个剧本后解锁新的历史剧本组，形成渐进式内容释放
- **成绩/评价机制**：每次通关后对玩家的历史改写给出趣味评级（如"颠覆程度"、"蝴蝶效应指数"、"历史修正力"），鼓励重玩
- **卡牌爽感强化**：决策牌的视觉效果和结果反馈更即时、更有冲击力
- **降低认知负担**：减少文本量，强化视觉引导

### B 路线：硬核历史模拟（面向历史爱好者）

**定位**：深度、严谨、高自由度。强调历史的复杂性和因果逻辑。

**关键方向**：

- **可存档的无尽模式**：打破四幕限制，玩家可以在一个历史剧本中持续推演，每次决定都分支出新走向
- **严谨的故事生成**：提示词对历史事实的约束更严格，架空结果必须有合理的因果链支撑
- **自定义文本输入**：玩家可以自由输入行动，而不是仅限于三张卡牌选择
- **因果链可视化**：展示每次决定的连锁反应如何影响后续历史

## 待办项（按优先级排序）

### P0：提示词架构重构

当前提示词架构是快速迭代的产物，存在多处不合理的设计：

- `outputContract` 以 KV 对象散列输出规范，模型阅读成本高（已部分修复为字符串拼接，见 `2026-07-30-output-contract-format.md`）
- 系统提示词与 Worker proxy 耦合（已修复，见 `2026-07-30-proxy-system-prompt-validation-400.md`）
- 紧凑键（`s`/`c`/`r`/`b`/`d`/`n`/`h`/`p`/`o`/`e`）在早期为了降低 token 消耗而引入，增加了解析复杂度，且不利于模型理解字段语义

需要做：

1. 还原被错误简化的键：评估哪些紧凑键可以还原为完整英文/中文键名，哪些必须保留（出于 token 或模型行为考量）
2. 统一系统提示词的风格和结构：每个场景类型的提示词遵循相同的段落结构
3. 建立提示词版本管理：每次修改记录变更原因和效果，方便回退
4. 设计更清晰的输出约束表达方式

### P1：Tap 工具完善

Tap（LLM Tap）是目前最重要的调试工具，需要持续完善：

- 输入端同时展示原始 JSON 和解析后结构（当前只有解析后）
- 新增"模型直接输入"展示模式：把模型原始响应按 token 渲染，方便排查格式问题
- 支持折叠/展开长字段
- 支持对比多次请求的差异
- 改进错误信息的可读性

### P2：双路线基础建设

- A 路线：设计剧本组解锁树、成绩评价算法、卡牌反馈增强
- B 路线：设计存档系统、无尽模式状态管理、自定义输入解析

### P3：复盘可视化

游戏结束后增加复盘页面，用可视化的方式呈现整局游戏的关键信息：

- **决策树图谱**：以树状图展示四次决定的分支路径，每条分支标注玩家选择与未选之路的对比
- **因果链流向图**：展示每次决定→直接结果→代价→受益/承担者的因果流向，帮助玩家理解"蝴蝶效应"的传导路径
- **历史偏差对比**：平行展示"正史原本"与"玩家改写后"的关键差异点，突出玩家改变了什么
- **回放模式**：按时间顺序快速回放四幕的关键节点（标题+决定+结果），可以截图分享

### P4：商业化探索（低优先级）

在不破坏核心体验的前提下，探索轻度商业化手段：

- **看广告复活**：某一幕推演失败后，观看广告重置当前幕（重新出牌）
- **看广告刷新卡牌**：对当前的三张牌不满意时，观看广告重新生成一组备选牌
- **原则**：广告只出现在重试/刷新场景，不干扰正常游戏流程；不出现在结局页面和剧本选择页

### P5：代码质量和可维护性

- 提示词相关代码与游戏逻辑的耦合需要解耦
- Worker proxy 的错误码体系需要完善（区分格式错误、版本冲突、服务不可用）
- 测试覆盖核心提示词变更的回归场景

## 非目标

以下方向不在当前规划内：

- 多人在线或社交功能
- 移动端原生应用（Web 优先）
- 商业化变现（聚焦产品体验）
- 非中文语言支持
